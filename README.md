# BusBidder Spain
**Live application:** [BusBidder Spain](https://acit4420exam-2-frontend.vercel.app/)

BusBidder is a web application for comparing bus travel offers to destinations in Spain. Users can choose a destination, set a budget and preferred departure time, and adjust how important different travel criteria are. The application ranks the available offers and explains why the highest-ranked offer was selected.

**Development history:** This submission represents a second attempt at developing BusBidder. The Git commit history from my initial attempt is included as a text file (`CommitHistoryfromPreviousProject.txt`) to document the development process leading up to the current implementation.

## Features

- Search for bus offers to Spanish destinations from Madrid.
- Select a traveller profile or adjust the ranking weights manually.
- Filter out offers that exceed the selected budget.
- Rank offers by price, journey duration, departure time, flexibility, customer rating, number of transfers, and environmental measure.
- View an explanation of the winning offer.
- Book an available seat and cancel an existing booking.
- Inspect the offer database, bookings, validation errors, and application logs.

The offer data is generated by the application and stored in a PostgreSQL database. It is not retrieved live from bus operators.

## Setup

### 1. Configure the database

Create a file named `.env` inside the `backend` directory and add your PostgreSQL connection string:

```env
DATABASE_URL=your_postgresql_connection_string
```

The backend reads this variable when connecting to PostgreSQL. Keep the connection string private and do not commit the `.env` file.

### 2. Install backend dependencies

From the project root, run:

```bash
cd backend
uv sync
```

### 3. Start the backend

While inside the `backend` directory, run:

```bash
uv run uvicorn main:app --reload --port 8000
```

The API will be available at `http://localhost:8000`. FastAPI's interactive API documentation is available at `http://localhost:8000/docs`.

### 4. Start the frontend

Open a second terminal and navigate to the `frontend` directory:

```bash
cd frontend
python -m http.server 5000
```

Open `http://localhost:5000/index.html` in your browser. The frontend is configured to use the local backend when accessed through `localhost`.

## How it works

1. The user chooses a destination, budget, preferred departure time, and traveller profile.
2. The frontend sends the selected values and ranking weights to the FastAPI backend.
3. The backend generates offers for the destination using the available bus-company data.
4. The validation module checks the generated offers. Invalid offers are excluded and their errors are stored in the database.
5. The ranking module normalizes the ranking criteria, calculates a weighted score for each offer, removes offers above the user's budget, and sorts the remaining offers by score.
6. The ranked offers are returned to the frontend, where they are displayed in a table.
7. The user can select an offer to book a seat. Bookings can later be viewed and cancelled on the bookings page.

The seven ranking criteria are price, duration, departure time, flexibility, customer rating, transfers, and environmental measure. The traveller profiles set default weights, which can also be adjusted using the sliders.

## Main API endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/getDB` | Retrieve stored travel offers |
| `POST` | `/newDatabase` | Generate a new set of offers and clear existing bookings and validation errors |
| `POST` | `/search/` | Generate, validate, and rank offers for a search |
| `GET` | `/explaneWinner/` | Return an explanation of the winning offer |
| `POST` | `/booking/` | Book a seat |
| `GET` | `/getBookings` | Retrieve bookings for a first and last name |
| `POST` | `/unBook/` | Cancel a booking |
| `GET` | `/getLog` | Retrieve application logs |
| `GET` | `/getAllErrors` | Retrieve validation errors |
| `DELETE` | `/deleteLog` | Clear application logs |
| `DELETE` | `/deleteBookings` | Clear all bookings |
| `DELETE` | `/deleteErrors` | Clear validation errors |
